# Changelog

## Unreleased

- **Nozomi and Dragos exports (experimental):** the importer also reads a Nozomi `node_cves` export (the JSON a query returns, or a CSV with the same fields) and a Dragos vulnerability-detections JSON export. They follow Nozomi's published data model and third-party descriptions of the Dragos API, have not been checked against a real export, and say so in the summary; a file that does not look like them is refused. Resolved records are skipped; the OT tools' vendor, product and firmware version fill the inventory, which feeds the version comparison; vendor risk scores, likelihoods and exploit intelligence are not used. A JSON file larger than 100 MB is refused (it is read whole). Samples are in the bundle. See docs/IMPORT.md.
- **Nessus `.nessus` files:** the importer also reads Nessus v2 XML exports, streaming them so a large file is never held in memory, keeping the same rules as the CSV (one finding per CVE, the v3 score first, informational items skipped and counted) and also skipping compliance checks, which are audits, not vulnerabilities. A file that declares a DTD or an entity is refused. A sample, `sample_scan.nessus`, is in the bundle. See docs/IMPORT.md.
- **Import scanner exports:** the new `ot_triage_import.py` turns a Nessus CSV, a Tenable Vulnerability Management CSV or an OpenVAS / Greenbone CSV into a findings file and, if you ask, an asset inventory that OT Triage ranks as usual. It skips resolved, fixed and informational findings and says how many; splits a plugin's CVEs into one finding each; leaves a missing score empty so the finding shows as not scored; merges the same finding reported by two tools through an optional aliases file; fills a new inventory with what the scan knows and never replaces a value you wrote or invents criticality, exposure or controls. Nothing is scored, nothing leaves your machine, and no input file is ever changed. Two fictional samples are in the bundle. See docs/IMPORT.md and the plan for the Nozomi and Dragos formats in docs/SCANNER_IMPORT.md.

## 0.8.0 (2026-10-13)

- **Version-aware advisory matching:** the asset inventory can now have an optional `version` column (aliases `firmware`, `firmware_version`, `fw_version`, `software_version`, `sw_version`). With a vendor, a product and a version, the tool compares the version with the versions each matching CISA advisory lists as affected (for example `<=Firmware_3.11.0` or `>=4.0|<5.2`). In **By asset**, the details say how many advisories list your version as affected, how many list other versions only and how many could not be compared; the advisories that list your version come first, each with a *Version check* line. In Batch's Findings view, each advisory of a row whose asset has a vendor, product and version gets the same line. The roll-up export gains `version` and `listing_your_version` columns. The tool reads the common shapes (about 94% of the version text in today's advisories) and says it could not compare, rather than guessing, for anything else. It is a pointer to read, never a verdict, and it never changes a bucket or an ordering score. The stored advisory index is about 1 MB larger and its format changes, so update the ICS advisories once after upgrading (the app says so if it finds the old one). See docs/INVENTORY.md.

### Upgrading from 0.7.0

- **Update the ICS advisories once.** The stored advisory index has a new format (it also keeps the versions each advisory lists as affected), so the app will say the stored copy could not be used until you press **Update threat data** again (about 12 MB) or import the archive. Nothing else is lost; KEV and EPSS are untouched.
- **Add a `version` column to your asset inventory if you want the comparison.** It is optional, and without it everything works as in 0.7.0. A version the tool cannot read as a number is reported as not compared.
- **Nothing about scoring changed.** The version comparison is context: no priority or ordering score is different from 0.7.0, and it is never worded as safe.
- **The roll-up export has two new columns,** `version` and `listing_your_version`, if a script reads that CSV by position rather than by name.

## 0.7.0 (2026-10-12)

- **CISA ICS advisories:** the Threat data view can now download CISA's public ICS advisories (the CSAF repository at github.com/cisagov/CSAF, about 12 MB) or import the archive from a file. A looked-up CVE shows which advisories name it: an **ICS advisories from CISA** card in Assess with links to each advisory's page on cisa.gov, a chip, a line in the reasoning, the copied summaries, the Batch Details box, and a new `ics_advisories` export column. Context only: the bucket and the ordering score never change. Only the OT advisory files are read from the archive and nothing is unpacked to disk; limits on size, entries and nesting, a skip-and-count rule for unreadable advisories, and links built from the validated advisory number rather than copied from the file. Security checkpoint CP8 in `reports/cp8-ics-advisories/`. The update now asks about three hosts (`www.cisa.gov`, `epss.empiricalsecurity.com`, `codeload.github.com`).
- **What the advisory says about a fix:** each advisory is also read for whether the vendor has a fix, a fix for only some products, no fix yet, no fix planned, or only a mitigation or workaround, for each CVE. It is shown beside the advisory, as a chip, in the reasoning, in Batch details, in a new `ics_remediation` export column, and as a note under Patch status in Assess. Patch status is never changed for you, and the bucket and the ordering score are unaffected.
- **What the vendor says to do:** the advisories' own remediation text is now kept too. Under each advisory, Assess and the Batch details list the vendor's steps for that CVE in the vendor's words, in the advisory's order, each marked *Fix*, *Mitigation*, *Workaround*, *No fix available* or *No fix planned*, with the vendor's link when it gave one (for example the firmware upgrade procedure). Assess shows up to eight steps for each advisory, Batch four, and both say how many more there are. **Copy summary** and **Copy as Markdown** include them, and the CSV export has a new `ics_remediation_steps` column (the newest advisory's steps, with their links, cut at 1,500 characters). The text is shown as plain text, a link opens only when you click it and only if it is a plain `https` address, and none of it changes a bucket or an ordering score. The stored index is about 5 MB (it was about 2 MB), and its format is new in 0.7.0.
- **Advisories that may apply to an asset:** the asset inventory can now have optional `vendor` and `product` columns. In Batch's **By asset** mode, selecting an asset lists the CISA ICS advisories that name that vendor and product (newest five, with links and the total), or says that none was found or that no advisory names that vendor. The asset roll-up export and the command line's `--assets` file gain `vendor`, `product`, `possible_advisories` and `newest_possible_advisory`. It is a pointer to read, not proof (it does not know your version), and it never changes a priority or a score.
- **Per-asset view:** Batch has a new **By asset** button. It groups the findings by `asset_id` and shows each asset's worst bucket, its NOW, NEXT and NEVER counts and its top finding, and lists what could be handled on one outage window. **Export asset roll-up** saves it as a CSV. Nothing here changes a priority.
- **Compare with a previous export:** in Batch, **Compare with previous…** reads an earlier ranked CSV (one saved with Export ranked CSV) and adds a **Change** column: *New*, *Up from NEXT*, *Down from NOW*, *Same*. The line above the table counts what is new, what moved up or down and what was resolved, and **Show resolved…** lists the findings that are gone. Findings are recognised by id, or else by CVE and asset, or else by name and asset; if more than one previous row could be the same finding it says so instead of guessing. The comparison is kept when you open a newer findings file, and the export gains `change` and `previous_priority` columns. Nothing here changes a priority.
- **Command line:** `ot_triage_cli.py` ranks a findings file without a window, with the same rules, settings and threat data: `python3 ot_triage_cli.py findings.csv -o ranked.csv`, with `--inventory`, `--compare`, `--assets`, `--top`, `--fail-on NOW|NEXT` (exit code 3 for scripts and scheduled jobs) and `--update` (the only thing that uses the network). Output files are never replaced without `--force`, input files never, and printed text is cleaned. See docs/CLI.md.
- **Portable bundle:** `python3 tools/make_bundle.py` builds `ot-triage-<version>.zip` (the application, documents and samples; no tests or tools) and a `.sha256` file. It is reproducible, so the checksum can be checked by anyone who builds it from the same tag. On Windows, double-click **OT Triage.pyw** in the unzipped folder (it needs Python 3.12 or newer with Tkinter, and shows a message box, not nothing, if it cannot start). There is deliberately no unsigned `.exe`. See docs/RELEASING.md.
- **OkieOTSec brand guide v1.1:** the dark and light themes now use the guide's palette (Oklahoma blue buttons with white text, navy header, sky links on dark, cream and ink surfaces, a copper rule), the guide's risk colours (NEVER is now grey, not green), and its fonts when installed (Space Grotesk for titles, IBM Plex Sans for text, IBM Plex Mono for values), falling back to the system fonts otherwise. The header reads "An OkieOTSec project".
- **OkieOTSec brand kit v1.1:** the real logo is in the application: the shield beside the title, the full lockup in the About view, and the app tile as the window icon (with the Windows `.ico`), all from the brand kit's own SVGs, plus the kit's exact theme colours. The README now shows the lockup and fresh screenshots (including the new By asset view). The images live in `assets/brand/` with a note on their source and on rights: the MIT licence covers the code, not the name and logo, and forks must replace them with their own.
- **Cleaner tabs:** the Ctrl+1 to Ctrl+5 hints are no longer drawn on the navigation tabs. The shortcuts still work and are listed in the README.
- **Stricter links:** an address that contains white space is no longer offered as a link (this could not happen with the KEV notes, which are split at spaces, but it can with the vendor links in the advisories).
- **Exact matching:** CVE ids, versions and dates read from the KEV and EPSS files must now match exactly; before, a trailing new line slipped past the pattern. It could never be looked up, so nothing was affected in practice.

### Upgrading from 0.6.0

- **The ICS advisories are new and are not downloaded until you ask.** Open Threat data and press **Update threat data** to fetch them (about 12 MB, three hosts now: `www.cisa.gov`, `epss.empiricalsecurity.com` and `codeload.github.com`). If you allow only specific hosts, add the third.
- **NEVER is now grey, not green,** and buttons are Oklahoma blue, to follow the OkieOTSec brand guide. Buckets, scores and rules are unchanged.
- **On a brand-new Windows install** the ICS advisories download can fail with "unable to get local issuer certificate" (Windows adds some trusted roots only when first needed). Certificate checking is never turned off; docs/THREAT_DATA.md has two ways around it, including importing the archive from a file.
- **Nothing about scoring changed.** The ICS advisory data, the By asset view, the comparison with an earlier export and the vendor and product matching are context and presentation: no priority or ordering score is different from 0.6.0.
- **Forks:** the OkieOTSec name and logo are not part of the MIT license; replace `assets/brand/` and the brand text in `gui_brand.py` in your own copy.

## 0.6.0 (2026-10-11)

- **Security requirements for the environmental score:** an optional section in Assess (Low, Medium or High for confidentiality, integrity and availability) and optional `confidentiality`, `integrity` and `availability` columns in the asset inventory now apply the CVSS security requirements to a CVSS vector, so an environmental score no longer needs a hand-built vector. Anything the vector sets itself is kept. The score is still shown for comparison only; the priority is unchanged. Samples: `sample_inventory.csv` (now with requirement columns) and `sample_findings_environmental.csv`. The section opens by itself when a CVSS vector is entered (closing it by hand sticks until the vector is cleared).

## 0.5.0 (2026-10-11)

- **Environmental CVSS scores:** a CVSS 3.0, 3.1 or 4.0 vector that sets environmental metrics (security requirements, modified base metrics; for 4.0 including the Safety value) now also gets an environmental score, shown next to the base score in Assess, the copied summaries, Batch details and a new `cvss_environmental` export column. The priority still uses only the base score (decided with the project owner; see docs/POLICY.md). Checked against FIRST's official calculators on about 180,000 generated vectors (every score identical); the 60,000 vectors per version are rebuilt and re-checked by the offline tests.
- **Asset inventory import:** in Batch, **Load inventory...** reads a CSV of assets (`asset_id`, criticality, exposure, controls) and fills those values into findings that carry an `asset_id`, so they no longer need typing on every row. A value on the finding row always wins; an unknown or duplicated asset is an error, never a guess. The open file is scored again whenever the inventory changes. The export gains `asset_id` and `from_inventory` columns. No rule changes. Sample files and docs in [docs/INVENTORY.md](docs/INVENTORY.md).
- **Test windows no longer take over your desktop:** `tools/headless_tests.py` runs the whole suite on a private virtual display (Xvfb) so no window opens on your screen, and the test helpers have an optional guard (`OT_TRIAGE_REQUIRE_PRIVATE_DISPLAY=1`) that keeps GUI tests off a real display. See docs/GUI_TESTING.md.
- **Asset column in Batch:** when the file has asset ids, the table shows each finding's asset, so several findings on one asset are easy to see; click the heading to group them, and the Name and Threat source columns now share the leftover width so the table fits any window. Sample: `sample_findings_multiple_per_asset.csv`.
- **Fixed:** the shared text cleaner turned line breaks and tabs into nothing, which could glue two words together (for example in a CISA note); they now become spaces.

## 0.4.0 (2026-10-09)

- **Software bill of materials:** `sbom/sbom.cdx.json` now describes OT Triage itself (version, license, project links) with no third-party components, and is generated reproducibly by `tools/make_sbom.py`; a test keeps it in step with the version.
- **References from CISA's notes:** the Assess view lists the links CISA adds to a KEV entry (advisories, vendor pages, BOD guidance) under Recommended action, each with its real domain. Links open in your browser only when you click them, only safe `https` links are clickable, and the copied summaries include them. See [docs/THREAT_DATA.md](docs/THREAT_DATA.md).
- **Changed:** looking up a CVE that is in CISA KEV now shows CISA's required action, the reference links and the KEV chips straight away, without waiting for a CVSS score. Only the priority itself needs the score, and it says so.
- **New name and branding:** the project is now **OT Triage by OkieOTSec** (it was "Vulnerability Prioritizer"). The window shows the OkieOTSec wordmark and a new icon (three bars in the result colours), the About page links to the project's website, GitHub, YouTube and X, and the light theme is now a warm cream. The entry point is `ot_triage_gui.py`, and the settings and data folders are now named `ot-triage` (an existing install should move its old `vuln-prioritizer` folders, or just download the threat data again).
- **Fixed:** a long message in the Assess inputs column (for example "No threat data is loaded") could make the column as wide as the message and push the results column off screen. All wrapping text now starts from a sensible width, and a test checks it.
- **Fixed:** a long sentence in front of a CISA link was shown as the link text; it is now shown as an explanation, with the domain as the link.
- **Code quality:** the lint rules are now listed explicitly in `ruff.toml` (bugs, security, import order, modern syntax, simplifications) and CI uses that file with a pinned ruff version. About 50 style findings were fixed; behaviour is unchanged (all tests pass and all 110,160 CVSS vectors still match FIRST's calculators).
- **Fixed (Windows):** a button stayed in its darker pressed colour after a click until the pointer moved; it now returns to normal at once.
- **Fixed:** pasting an enormous text into a text box could freeze the app on Windows (Tk becomes extremely slow showing megabytes on one line). Text boxes now refuse input beyond 2,000 characters immediately, and the CVSS vector box says so. Layout switches and the scrollbar also no longer flip back and forth in some window sizes, which made the interface stall on some systems.
- **License:** the project is released under the MIT License (see [LICENSE](LICENSE)).
- **Fixed:** strong compensating controls did not lower the ordering score, so an item with strong controls could rank above the same item with partial controls (for example an actively exploited item already at NEXT). Strong controls now take 1.0 off the ordering score (partial still 0.5), and a test checks that better controls never rank higher. Buckets are unchanged. See [docs/POLICY.md](docs/POLICY.md), rule 4.
- **More from the KEV data:** the Batch Details box lists a row's CISA references (compact, with a scrolling area so long details never hide the table), the CSV export gains `references` and `forensic_triage` columns, and entries CISA flags for forensic triage get a neutral "Forensic triage advised" chip. None of these change a bucket or score.
- **Text size shortcuts:** Ctrl+plus, Ctrl+minus and Ctrl+0 make the whole interface larger or smaller (90% to 130%) or reset it, and the choice is remembered. This helps on window managers where resizing the window is awkward.
- **Clearer Windows certificate error:** on a fresh Windows install the EPSS download can fail with "unable to get local issuer certificate" because Windows has not installed a trusted root yet. The message now points to a verified fix in [docs/THREAT_DATA.md](docs/THREAT_DATA.md) (install Amazon Trust's published root, checked against its SHA-256). Certificate checking stays on.
- **Fixed:** in the Batch view the Details box could be cut off in shorter windows; the results table now gives up space first.
- **Fixed:** in the Batch view the loading progress bar could be squeezed out of sight by the results table in short windows; it now sits directly under the toolbar.
- **Fixed:** the headline in the Priority card (for example "Schedule remediation") was cut off in medium-width windows; it now wraps onto a second line.
- **Fixed:** changing the threat level in the Assess view could show an extra "unexpected error (TclError)" box after the override reason prompt, because the dialog tried to take the keyboard grab before the window manager had shown it. The grab is now retried until the window is visible and can never raise.
- **CVSS vectors:** paste a CVSS 3.0, 3.1 or 4.0 vector in the Assess view to fill in the base score, or add a `cvss_vector` column to batch files. Scores match FIRST's official calculators for every possible base vector. See [docs/CVSS.md](docs/CVSS.md).
- **New GUI:** Assess, Batch, Threat data, Settings and About views with dark and light themes, a status bar showing threat data freshness, keyboard shortcuts, and a "What would change this?" panel.
- **Visual polish:** modern typeface, rounded cards, buttons, chips and inputs, a refined sidebar, and layouts that work down to a 700 px wide window.
- **Threat data:** CISA KEV and EPSS lookups from local files, user-started updates with progress and cancel, offline import, freshness warnings.
- **Adjustable scoring:** the two CVSS lines, the EPSS cutoff and the stale-data limit, with validation and a visible "Custom scoring" badge.
- **Rules updated** (see [docs/POLICY.md](docs/POLICY.md)): actively exploited, exposed crown jewels are NOW at any CVSS score; exposed crown jewels are never below NEXT; partial controls only affect the ranking score.
- **Security:** hostile-input handling for every file the tool reads, atomic user-only file writes, an HTTPS-only downloader with size, time and redirect limits, formula-safe CSV export, and a test that keeps invisible or look-alike characters out of the source. See [SECURITY.md](SECURITY.md).
